Agent Execution · Max-10-Round Loop · SSE Streaming Agent 执行 · 最多 10 轮循环 · SSE 流式传输
Agent Loop & Tool Dispatcher Agent 循环与工具调度
10 Tools SSE Stream Citations Matter FSM Gate Repeatable / LongHorizon
10 个工具 SSE 流 引文 Matter FSM 闸门 标准化 / 长周期
Component / ItemDetails
Loop (max 10 rounds)Build context (prior events + tool summaries) → Call LLM → Parse tool calls → Dispatch → Append results → Iterate → Extract citations → Stream SSE to client
10 toolskb_search · read_document · write_section · insert_clause · delete_clause · get_diff · list_matters · get_matter · send_message · table_review
Mode A — RepeatableDeterministic checklist steps; AI drives each step; scalable to batch. Use cases: data compliance questionnaire, standard NDA/DPA checklist, cross-border data flow audit
Mode B — LongHorizonPlan → Lawyer confirms plan → Execute; low-risk decisions logged automatically; high-risk decisions pause + escalate. Use cases: PE/VC TS+SPA+SHA full review, cross-border compliance chain analysis
Hard gate (Matter FSM)Any high-risk tool call → MatterState::LawyerReview immediately, regardless of loop position. No formal output delivered until MatterState::Approved
Confidence gapRAG cosine below threshold → agent outputs "依据不足，需律师复核" + sets MatterState::NeedsRevision — never fabricates a regulatory citation
组件 / 项目说明
循环（最多 10 轮）构建上下文（历史事件 + 工具摘要）→ 调用 LLM → 解析工具调用 → 分派执行 → 回写结果 → 继续迭代 → 抽取引文 → 通过 SSE 推送到客户端。
10 个工具kb_search、read_document、write_section、insert_clause、delete_clause、get_diff、list_matters、get_matter、send_message、table_review。
模式 A：标准化采用确定性的清单式步骤，由 AI 推进每一步，并可扩展到批量任务。典型用例包括数据合规问卷、标准 NDA / DPA 检查与跨境数据流审计。
模式 B：长周期遵循 Plan → 律师确认计划 → Execute 的回路；低风险决策自动记录，高风险决策暂停并升级。典型用例包括 PE / VC TS + SPA + SHA 全量审查与跨境合规链分析。
硬闸门（Matter FSM）任何高风险工具调用都会立即把状态推入 MatterState::LawyerReview，不受当前循环位置影响；正式输出在进入 MatterState::Approved 前不得交付。
置信缺口当 RAG 余弦相似度低于阈值时，agent 输出 "依据不足，需律师复核" 并将状态设置为 MatterState::NeedsRevision，绝不编造监管引用。

Document Engineering · OOXML · Word-Level Tracked Changes 文档工程 · OOXML · 词级修订标记
DOCX Engine Pipeline DOCX 引擎流水线
3 Paths w:ins / w:del get_diff Self-Review Parallel Sub-Agents +40% Edit Acceptance
3 路径 w:ins / w:del get_diff 自检 并行子 Agent +40% 编辑接受率
Component / ItemDetails
Path A — GenerateBuild new DOCX from JSON structure: metadata block → section paragraphs → embedded tables → style application → ZIP packaging via quick-xml. Used for: compliance reports, contract templates, table review exports
Path B — Edit (tracked changes)Agent operates on in-memory document representation via structured tool calls (get_section / write_section / insert_clause / delete_clause) — never edits raw XML directly
get_diff self-reviewAfter generating all edits, agent calls get_diff to self-review changes before committing — catches self-contradictions and numbering errors
OOXML revision markupCommitted edits produce <w:ins> / <w:del> elements with w:author="Pacgate AI" + timestamp — proper review surface, not silent overwrite
Parallel sub-agentsLarge documents: each major section assigned to a sub-agent; orchestrator merges non-conflicts automatically; conflicting edits escalate
Path C — ParseExtract from existing DOCX: parties, clauses, tables, dates, obligations, governing law — for RAG ingestion and clause-parser WASM analysis
Harvey benchmark+40% edit acceptance rate verified · +70% weekly active user query growth
Diff engineRust similar crate (word-level) → OOXML <w:ins>/<w:del> via quick-xml
组件 / 项目说明
路径 A：生成从 JSON 结构生成新的 DOCX：元数据块 → 段落章节 → 嵌入式表格 → 样式应用 → 通过 quick-xml 打包 ZIP。适用于合规报告、合同模板与表格化审阅导出。
路径 B：编辑（修订模式）Agent 通过结构化工具调用操作内存中的文档表示（get_section / write_section / insert_clause / delete_clause），绝不直接编辑原始 XML。
get_diff 自检完成全部修改后，agent 先调用 get_diff 对自身改动做复核，再决定是否提交，以减少自相矛盾与编号错误。
OOXML 修订标记所有提交的修改都会生成 <w:ins> / <w:del> 元素，并写入 w:author="Pacgate AI" 与时间戳，形成可审阅的正式修订面，而非静默覆盖。
并行子 Agent在大型文档中，每个主要章节可分配给单独子 Agent 处理；总控负责编排无冲突合并，冲突编辑则升级处理。
路径 C：解析从既有 DOCX 中抽取主体、条款、表格、日期、义务与 governing law，用于 RAG 摄入与 clause-parser WASM 分析。
Harvey 基准已验证 +40% 编辑接受率，且周活跃用户查询量增长超过 +70%。
Diff 引擎使用 Rust similar crate 做逐词比对，再通过 quick-xml 生成 OOXML <w:ins>/<w:del>。

RAG & Knowledge Base Pipeline RAG 与知识库流水线
Authority Registry pgvector IVFFlat RRF Fusion Re-rank NPU Embeddings Client KB
权威登记库 pgvector IVFFlat RRF 融合重排 NPU 嵌入 客户知识库
Component / ItemDetails
Ingest pipelineDocument upload → text extract (DOCX/PDF/TXT) → chunk (512 tokens, 64-token overlap, sentence-boundary aware) → embed via nomic-embed-text on XDNA NPU → pgvector upsert (vector(768), IVFFlat index) + tsvector GIN index
Retrieval pipelineEmbed query (NPU) → cosine similarity search (pgvector) + tsvector full-text search → RRF (Reciprocal Rank Fusion) re-ranking → top-K context injection into agent prompt
Authority RegistryRegulatory laws (PIPL, DSL, CSL, AIGC rules, SFC rules, CAC rules), compliance checklists, internal standard positions, historical project experience, client playbooks, delivery templates — curated by partners, versioned with effective dates
Client KBPer-matter: uploaded contracts, prior opinions, counterparty profiles, preference history — auto-indexed and linked to client playbook
Chunk metadatasource · version_date · jurisdiction · applicability_scope · superseded_by · citation_priority
Confidence gapRAG cosine below threshold → "依据不足，需律师复核" — never fabricates a regulatory citation
EmbedderDefault: nomic-embed-text via Ollama (local, XDNA NPU) — switchable to OpenAI/Qwen embeddings per tenant
Phase 4 legal data北大法宝 / 威科先行 API connector (parallel business negotiation track)
组件 / 项目说明
写入流水线文档上传 → 文本提取（DOCX / PDF / TXT）→ 切块（512 token、64-token overlap、按句边界处理）→ 通过 XDNA NPU 上的 nomic-embed-text 生成嵌入 → 写入 pgvector（vector(768)、IVFFlat 索引）并同步写入 tsvector GIN 索引。
检索流水线查询嵌入（NPU）→ pgvector 余弦相似度检索 + tsvector 全文检索 → RRF（Reciprocal Rank Fusion）重排 → 将 top-K 上下文注入 agent 提示词。
Authority Registry涵盖 PIPL、DSL、CSL、AIGC 规则、SFC 规则、CAC 规则等监管依据，以及合规清单、内部标准立场、历史项目经验、客户 playbook 与交付模板，由合伙人维护并按生效日期进行版本管理。
Client KB按 matter 组织客户上传合同、历史法律意见、交易对手档案与偏好记录，并自动索引后与客户 playbook 关联。
Chunk 元数据source、version_date、jurisdiction、applicability_scope、superseded_by、citation_priority。
置信缺口当 RAG 余弦相似度低于阈值时，系统输出 "依据不足，需律师复核"，绝不编造监管引用。
嵌入器默认使用 Ollama 本地运行的 nomic-embed-text（XDNA NPU），并可按租户切换至 OpenAI / Qwen embeddings。
第四阶段法律数据接入北大法宝 / 威科先行 API 连接器，作为并行业务合作推进项。
