Core Feature Modules核心功能模块
📄
DOCX Engine
OOXML ZIP builder · Word-level tracked changes via similar crate · Legal heading hierarchy (1. → 1.1 → (a) → (i)) · Signature page generation · 9 legal templates
🔍
RAG Pipeline
512-token chunks · pgvector cosine similarity · Postgres tsvector keyword search · RRF fusion ranking · Jurisdiction + practice area tagging
📋
Tabular Review
N documents × M questions grid · Parallel Tokio task pool (max 8 concurrent) · SSE streaming progress · XLSX export · Cell-level agent reasoning
⚖️
Citation System
Inline [1] markers · <CITATIONS> JSON block · Verbatim ≤25 words per citation · Post-generation citation integrity verification · Linked to source document
🎭
Persona Engine
12 international legal personas · 8 China-specific personas (涉外律师, 合同律师, 知识产权律师 …) · Per-matter persona selection · Jurisdiction-aware system prompts
🔗
MCP Integration
Pacgate exposes tools as MCP server · MCP client connects to DMS, 飞书/企微/钉钉, OA systems, calendar · Hermes persistent agent memory + scheduling
📖
Authority Registry
Separate KB store for statutes, regulations, and circulars. Each chunk carries: source / version_date / jurisdiction / applicability_scope / superseded_by / citation_priority. If no authoritative basis found, agent emits “依据不足，需律师复核” rather than hallucinating — feeding directly into MatterState::NeedsRevision.
🤖
Dual-Mode Agent
WorkflowMode::Repeatable (Type A): fixed tool sequence, deterministic, compliance-grade. WorkflowMode::LongHorizon (Type B): multi-round, self-review via get_diff, parallel sub-agents for clause-level tasks. Mode selected per matter type at intake.
📉
Confidence Gap Handling
When Authority Registry search returns cosine < threshold: agent inserts confidence flag, sets MatterState to NeedsRevision, blocks delivery. Lawyer receives annotated draft with flagged clauses. No auto-delivery on uncertain legal ground.
Matter State Machine · 案件状态机 (11 States)
Submitted → IntakeChecking → NeedsClientInfo → QueuedForAI → AIProcessing → LawyerReview ★ → Approved → Delivered → FollowUp / Closed
★ LawyerReview — Mandatory Gate
No matter bypasses lawyer review. Every AI-generated output lands in LawyerReview before it can reach Approved. Confidence gap → NeedsRevision.
NeedsRevision (re-entry)
Any state from LawyerReview may transition to NeedsRevision. Agent re-runs with lawyer notes. Revision loop is bounded and audited.
Immutable Audit Entries
Every state transition appends an immutable audit record: actor, timestamp, prev_state → next_state. Chain is tamper-evident by design.

N 份文档 × M 个问题网格 · 并行 Tokio 任务池（最多 8 并发）· SSE 流式进度 · XLSX 导出 · 单元格级 agent 推理

行内 [1] 标记 · <CITATIONS> JSON 块 · 每条引文 verbatim ≤25 词 · 生成后引文完整性校验 · 回链源文档

Persona 引擎
12 个国际法律 persona · 8 个中国法 persona（涉外律师、合同律师、知识产权律师等）· 按 Matter 选择 persona · 面向法域的系统提示词

Pacgate 以 MCP server 方式暴露工具；MCP client 可连接 DMS、飞书 / 企微 / 钉钉、OA 系统与 calendar；Hermes 提供持久 agent 记忆与调度。

权威登记库
独立知识库存放 statutes、regulations 与 circulars。每个 chunk 带有 source / version_date / jurisdiction / applicability_scope / superseded_by / citation_priority。若未找到权威依据，agent 输出“依据不足，需律师复核”，并直接进入 MatterState::NeedsRevision。
🤖
双模式 Agent
WorkflowMode::Repeatable（Type A）用于固定工具序列、确定性、合规级任务；WorkflowMode::LongHorizon（Type B）用于多轮推理、自我复核和 clause-level 并行子 Agent。模式在 intake 时按 Matter 类型选择。
📉
低置信度处理
当 Authority Registry 检索结果余弦相似度低于阈值时，agent 会插入置信标记，将 MatterState 设为 NeedsRevision，并阻止交付。律师收到的是带标记条款的草稿，而不是不确定情况下的自动交付。
案件状态机（11 个状态）
已提交 → 受理检查中 → 待补充客户信息 → 排队待 AI → AI 处理中 → 律师复核 ★ → 已批准 → 已交付 → 跟进 / 结案
★ 律师复核：强制闸门
任何 Matter 都不能绕过 LawyerReview。所有 AI 生成结果都必须先进入律师复核，之后才可能到达 Approved。一旦出现置信缺口，就直接进入 NeedsRevision。
NeedsRevision（重入）
从 LawyerReview 出发，任何 Matter 都可能转入 NeedsRevision。Agent 会携带律师批注重新执行，修订回路有边界、可审计。
不可变审计记录
每次状态迁移都会追加不可变审计记录，包含 actor、timestamp、prev_state → next_state。整条链路从设计上就是防篡改的。
