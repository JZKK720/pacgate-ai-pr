Core Differentiators · 核心差异化
01
Dedicated AIPC + Private Mesh专属 AIPC + 私有 Mesh
Sensitive matters can run on Pacgate-controlled dedicated Cubecloud Ryzen AI AIPC or workstation units, while multiple private local nodes can be joined over Tailscale under Cubecloud Agent OS. Documents, conversations, and keys stay inside Pacgate-controlled infrastructure rather than moving into a shared public-cloud workflow.
02
BYOK Tenant ModelBYOK 租户模型
Tenants supply their own LLM API keys. Keys are AES-256-GCM encrypted at rest, decrypted only inside the Ironclaw TEE vault at inference time. Neither Cubecloud nor Pacgate hold plaintext keys at any layer.
03
Chinese Law Native中国法律原生
8 China-specific legal personas (涉外律师, 合同律师, 知识产权律师, 劳动律师 …). System prompts and workflows in Simplified Chinese. 北大法宝 / 威科先行 data API integration path. Legal numbering follows PRC convention.
04
Cubecloud OS Integration智方云 OS 集成
Not a standalone app — Pacgate AI is an integrated surface of Cubecloud Agent OS. Matters → OpenSpace lineage. Review → Ironclaw TEE. Research → Hermes persistent memory. Draft → OpenCode LSP. Workflow → Warp ADE routing.
05
AMD RyzenAI StackAMD RyzenAI 算力栈
Cubecloud Ryzen AI stations use AMD XDNA NPU for embedding and prompt/prefill acceleration, AMD Radeon GPU for model decode, and CPU fallback for resilience. On supported units, 33B–35B class local models can exceed 50 tok/s eval and prompt/prefill can reach up to ~5,000 tok/s; MAX 395 class hardware can reach up to ~200 tok/s eval. This makes dedicated local deployment commercially viable against public-cloud legal AI pricing.
06
Rust + WASM Safety CoreRust+WASM 安全核心
Server logic in Rust: memory-safe, OWASP-clean, no GC pauses. Compliance validation in WASM modules inside Ironclaw TEE: sandboxed, signed, no network access. TypeScript/Python LLM wrapper risks (prompt injection, path traversal) eliminated at language level.
07
Compliance-First Product Lines合规优先产品线
Phase 1 launches three vertical compliance products on shared infrastructure: (1) Data compliance / cross-border data (PIPL · DSL · CSL); (2) AI product compliance (AIGC · CAC algorithm filing); (3) Web3 / RWA product compliance. Phase 2: commercial contract review, PE/VC investment agreement, redline + negotiation. Each product line shares the same Matter workflow engine — only the rule-mapping layer differs.
08
Matter-Centric, Not Chat-Centric以案件为中心
Every client engagement is a structured Matter with an 11-state FSM: submitted → intake_checking → queued_for_ai → ai_processing → lawyer_review → approved → delivered → closed. Clients never trigger agents directly. Formal legal output is only visible after ReviewDecision::Approved. Compared to Crosby (auto-delivers) and Moritz (20% spot-check), Pacgate AI's mandatory approval gate is a compliance and liability differentiator for the Chinese market.

核心差异化
01
专属 AIPC + 私有 Mesh
敏感事项可以运行在 Pacgate 可控的 Cubecloud Ryzen AI AIPC 或一体式工作站上，多个本地私有节点也可在 Cubecloud Agent OS 下通过 Tailscale 连接成私有 mesh。文档、会话与密钥保留在 Pacgate 可控基础设施中，而不是进入共享的公有云工作流。
02
BYOK 租户模型
租户自行提供 LLM API 密钥。密钥以 AES-256-GCM 静态加密保存，仅在推理时于 Ironclaw TEE vault 内解密。无论 Cubecloud 还是 Pacgate，都不会在任何层持有明文密钥。
03
中国法律原生
内置 8 个中国法特定 persona，例如涉外律师、合同律师、知识产权律师、劳动律师等。系统提示词和工作流以简体中文为主，并预留北大法宝 / 威科先行数据接口接入路径。法律编号体系遵循中国惯例。
04
智方云 OS 集成
Pacgate AI 不是独立应用，而是 Cubecloud Agent OS 的一组集成能力面。案件进入 OpenSpace 做谱系与审计，复核在 Ironclaw TEE 中执行，研究沉淀到 Hermes 持久记忆，草拟由 OpenCode LSP 驱动，工作流通过 Warp ADE 编排。
05
AMD RyzenAI 算力栈
Cubecloud Ryzen AI 站点使用 AMD XDNA NPU 承担 embedding 与 prompt / prefill 加速，AMD Radeon GPU 承担模型 decode，并保留 CPU 回退链路以确保韧性。在适配设备上，33B–35B 级本地模型 eval 吞吐可超过 50 tok/s，prompt / prefill 可达约 5,000 tok/s；MAX 395 级硬件可达到约 200 tok/s eval。这让专属本地部署在商业上足以对抗公有云法律 AI 定价。
06
Rust + WASM 安全核心
服务端逻辑基于 Rust，具备内存安全特性、易于做 OWASP 清洁交付，也没有 GC 停顿。合规校验运行在 Ironclaw TEE 内的 WASM 模块中，具备沙箱、签名与断网能力，从语言层规避常见的 TypeScript / Python 包装器风险。
07
合规优先产品线
第一阶段先落三条垂直产品线，并共享同一套底层基础设施：(1) 数据合规 / 跨境数据（PIPL · DSL · CSL）；(2) AI 产品合规（AIGC · CAC 算法备案）；(3) Web3 / RWA 产品合规。第二阶段扩展到商事合同审查、PE/VC 投资协议、红线与谈判。各条线复用同一 Matter 工作流引擎，只在规则映射层区分。
08
以案件为中心，而非以聊天为中心
每一个客户委托都会变成一个结构化 Matter，并经历 11 状态 FSM：submitted → intake_checking → queued_for_ai → ai_processing → lawyer_review → approved → delivered → closed。客户不能直接触发 agent；正式法律输出只有在 ReviewDecision::Approved 后才可见。相较 Crosby 的自动交付和 Moritz 的 20% 抽查，Pacgate AI 的强制审批闸门，更适合作为中国市场的合规与责任差异化卖点。
