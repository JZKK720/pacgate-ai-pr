#### 架构设计

- **核心架构**：多 Agent 辩论协议（Multi-Agent Debate Protocol）。67 个专家 Agent（59 专家 + 7 编排器 + 1 基础编排器），每个 Agent 有独立的系统提示、MCP 工具权限和辩论槽位。
- **工作流**：9 种工作流模板——从单专家咨询到全对抗审查。
- **三层验证**：评估器门控 → 对抗辩论（红队/蓝队） → 10-pass 验证管线（上下文/UX/清晰度/结构/准确性/完整性/风险/格式/法律设计/交付）。
- **Human Gate**：关键发现不自动交付，需人工审批。
- **Precedent Board**：跨会话持久记忆，可复现模式被强化、过时模式衰减。
- **Clawern 守护进程**：30 分钟心跳自主监控文件夹，支持 Telegram/邮件/macOS 通知、成本预测、多客户端隔离。
- **多模型支持**：✅ 支持 Anthropic / Mistral / Ollama，通过 provider 抽象层切换。
- **Agent 模式**：✅ 核心设计就是 Agent 架构，包含自主守护进程（Clawern）。

#### 功能覆盖

**核心功能**：
- ✅ 文档分析（PDF/DOCX/MD/TXT 解析 + 消毒）
- ✅ 多 Agent 辩论审查
- ✅ 合同审查（附带 CUAD/MAUD/ACORD 等 5 个法律数据集）
- ✅ 法律文档汇编 + 格式转换
- ✅ 审计追踪（结构化发现 + 辩论决议 + 验证结果 + 成本日志）
- ✅ 实时 Dashboard（Agent 活动、门控审批）
- ✅ 自主监控（Clawern）
- ✅ MCP 远程桥接（JSON-RPC，对接 Anthropic Managed Agents）
- ✅ 预算控制（每会话 USD 上限）
- ✅ A2A Agent Card（`.well-known/agent.json`）

**缺失功能**：
- ❌ 无向量检索/嵌入层（仅 BM25 FTS5）
- ❌ 无持久化任务队列（无 Redis/重试/死信）
- ❌ 无公开质量基准
- ❌ 多 Agent 辩论不完美（Agent 有时不互相倾听）
- ❌ Counsel 交付较慢（5-10 分钟/次）

#### 架构设计

**四层架构**：

**Layer 1: 38 步异步管线**
- 状态机驱动，6 个阶段：Setup → Discovery → Analysis → Cross-Domain → Quality → Reporting
- 支持断点续跑（checkpoint/resume），崩溃从当前步骤恢复
- 步骤类型化，状态对象可序列化为 JSON

**Layer 2: 13 个 Agent**
- 9 个专家 Agent：Legal / Finance / Commercial / ProductTech / Cybersecurity / HR / Tax / Regulatory / ESG
- 4 个元 Agent：Judge（质量审查）/ Executive Synthesis（综述+Go/No-Go）/ Red Flag Scanner（交易杀手扫描）/ Acquirer Intelligence（买方战略适配）
- 专家并行执行（按资源约束分批），元 Agent 在专家完成后顺序执行

**Layer 3: 神经符号交叉域分析**
- 确定性规则引擎（纯 Python，无 LLM 调用），7 条内置跨域触发规则：
  - Finance → Legal：收入确认问题 → 合同可执行性复查
  - Legal → Finance：控制权变更条款 → 财务风险量化
  - Legal → Finance：便利终止条款 → 收入风险计算
  - Legal → ProductTech：IP 所有权争议 → 技术依赖评估
  - ProductTech → Legal：数据隐私发现 → DPA/GDPR 合规审查
  - Commercial → Finance：SLA 风险 >10% 服务抵扣 → 财务量化
  - Finance → Commercial：定价差异 → 商业费率卡验证
- 触发后执行针对性 pass-2 复查（仅复查引用的合同，非全量），预算受限

**Layer 4: 5 道阻断式质量门**
1. **覆盖率门控**：是否分析了每个分配的文档？
2. **Schema 验证**：每个发现是否有必填字段（severity/citations/category）？
3. **引用核实**：能否追溯到具体页码和原文引用？（fuzzy match ≥ 80）
4. **语义去重**：两个 Agent 是否对同一文档说了同样的话？（rapidfuzz token_sort_ratio ≥ 80）
5. **数字审计**：财务数据是否与源文档匹配？（6 层确定性审计）
- **Fail-closed**：验证失败则管线停止，不静默产出错误结果

**防幻觉设计（5 层）**：
1. Pydantic schema 验证每个响应
2. 强制引用（file_path/page/exact_quote 对源验证）
3. "NOT_FOUND" 逃逸阀（找不到就说找不到，不编造）
4. 对抗式 Judge 审查（"这个发现看起来是编造的——用直接引用证明它"）
5. 6 层确定性数字审计

**其他关键设计**：
- **Map-merge-resolve**：大文档按页边界分块（150K 字符，15% overlap），独立分析后合并（优先逻辑：YES beats NO, specific beats generic），仅分块分歧时调用 LLM 仲裁。准确率从 74% → 95%，纯工程手段。
- **Agent 安全护栏**：硬限制 turn 数（soft 200, force-kill 3x）、路径保护（仅写 `_dd/`）、bash 模式拦截（24 个 blocked patterns，禁 `rm -rf`/`sudo`/pipe-to-shell）
- **Agent 可定制**：编辑 markdown 即可调整 persona/focus/severity（无需改 Python），安全规则不可移除
- **Knowledge Compounding**：增量 wiki 模式（受 Karpathy LLM Wiki 启发），知识编译一次后持续更新

1. MIT 许可证最宽松，无商用约束
2. 已有完整的多租户、认证、计费、知识库 RAG、文档处理链

4. Clawern 式守护进程（自主监控 + 心跳）
5. 审计追踪 + 成本控制

需要从 dd-agents 借鉴的关键设计：
1. 神经符号交叉域分析（规则引擎自动触发跨域复查）
2. 5 道阻断式质量门（覆盖率/Schema/引用核实/语义去重/数字审计）
3. 5 层防幻觉设计（特别是 NOT_FOUND 逃逸阀 + 对抗式 Judge 审查）
4. Map-merge-resolve 大文档处理（分块→独立分析→合并仲裁，准确率 74%→95%）
5. Agent 安全护栏（turn 限制 + 路径保护 + bash 模式拦截）

**Phase 3（垂直场景接入）**：**dd-agents 独立部署** + 中国法律底座自建

dd-agents 作为 M&A 尽调垂直模块：
1. 独立部署（pip install / Docker），作为系统 A 的一个专业工具
2. Agent persona 本地化（编辑 markdown，加入中国法律/合规检查项）
3. 输出报告中文化
4. 未来通过 API 网关与 Suzie Law 主系统集成

中国法律底座自建：

1. 构建中国法律上下文图谱（法条关联、案例索引、裁判规则）
2. 接入中国法律数据源（裁判文书网、法律法规库、司法解释等）
3. 中文 Persona 和 Agent 提示工程
4. 合同/案件知识库中文本地化

## 七、合规总模块设计（新增）

### 模块定位

合规作为 AI Law Firm 系统的核心总模块，统一管理各类合规场景。下设多个子模块，首期重点建设进出口合规，后续逐步扩展数据合规、劳务合规等领域。服务于系统 A（律师自用）和系统 B（客户交互）。

### 各子模块核心功能规划

#### 1. 进出口合规模块

##### 1.1 出口管制分类（ECCN / CCL）
- **美国 EAR**：商品控制清单分类（CCL/ECCN）
- **中国出口管制法**：两用物项出口许可分类
- **EU Dual-Use Regulation**：欧盟两用物项分类
- **实现方式**：AI 辅助分类（产品描述 → 建议分类 + 置信度 + 许可证要求）
- **参考**：EximAgent CLI 的 HS 编码分类思路

##### 1.2 关税与贸易救济
- HS/HTS 编码分类建议
- 反倾销/反补贴税率查询
- 关税计算（含 FTA 优惠税率判定）
- 原产地规则验证（FTA 合规）

##### 1.3 贸易合规审查工作流
- 合同贸易合规条款审查
- 进出口许可证管理
- 贸易合规风险评估报告

##### 1.4 法规追踪与更新
- 中国出口管制法、外商投资法
- 美国 EAR/BIS 规则更新
- EU Dual-Use Regulation 修订
- 日本/韩国等贸易管制法规
- AI 自动监控法规变更 + 推送影响分析

#### 2. 制裁合规模块（从进出口合规独立）

##### 2.1 制裁名单筛查
- **基础组件**：OpenSanctions/yente（MIT, Python/FastAPI）
  - 覆盖 OFAC SDN、EU 制裁名单、UN 制裁名单、UK OFSI 等
  - 模糊匹配 + 批量筛查 + 本地部署
  - yente-client 提供 MCP server，AI Agent 可直接调用

##### 2.2 50% Rule 分析
- 实益所有权穿透分析（被制裁实体持股 ≥50% 的关联实体自动识别）
- 股权结构图谱构建 + 受制裁节点标记

##### 2.3 二级制裁风险评估
- 美国二级制裁（secondary sanctions）对中国企业的适用性分析
- 重大交易判定（significant transaction test）
- 风险等级评分 + 缓释建议

##### 2.4 阻断法案冲突分析
- 中国《反外国制裁法》/ EU Blocking Statute 与美国制裁的冲突
- 合规矛盾场景的决策路径推荐

##### 2.5 中国制裁反制措施
- 中国实体清单、不可靠实体清单、反制裁清单
- 实时监控 + 变更提醒（清单更新推送）

#### 3. 数据合规模块

##### 3.1 数据隐私法规知识库

##### 3.2 数据处理协议（DPA）自动审查

##### 3.3 隐私影响评估（PIA）

#### 4. 数据跨境合规模块（从数据合规独立）
