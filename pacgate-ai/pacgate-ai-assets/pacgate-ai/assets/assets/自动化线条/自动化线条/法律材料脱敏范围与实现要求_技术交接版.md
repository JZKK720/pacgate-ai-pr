# 法律材料脱敏范围与实现要求

**版本：** v1.0  
**日期：** 2026年9月13日  
**用途：** 向另一套AI系统及其技术团队交接脱敏需求。  
**状态：** 需求与验收基线，不代表接收系统已实现或通过验收。

## 1. 目标与适用范围

本方案适用于合同审阅、法律尽职调查、数据合规分析、证据分析及法律报告生成等场景。

默认流程为：

> 本地解析 → 本地识别与去标识化 → 出站校验 → 云端分析 → 本地校验与身份还原 → 人工审阅及成品输出。

核心目标：**默认隐藏当事人及项目身份，完整保留分析所需的业务事实；对可能反查身份的信息结合上下文处理。**

本文件中的“脱敏”主要指可在本地还原的去标识化，不承诺所有材料均达到法律上的匿名化标准。业务模式可以调整识别重点，但不能降低基础身份保护范围。

## 2. 默认脱敏范围

| 类别 | 典型内容 | 默认处理 | 保留要求 |
|---|---|---|---|
| 本项目自然人身份 | 当事人、联系人、员工、股东、家庭成员等姓名及可识别别名 | 替换为稳定占位符 | 保留其角色、身份性质及与其他主体的关系 |
| 本项目机构身份 | 客户、交易对方、关联公司、股东、雇主、涉事金融机构等名称及识别性简称 | 替换为稳定占位符 | 保留公司、银行、基金、律所等主体类型及业务角色 |
| 身份与登记号码 | 身份证、护照、统一社会信用代码等 | 替换为稳定占位符 | 保留证件类型；分析需要的属性应单独提取并校验 |
| 联系方式 | 手机、电话、个人或项目联系邮箱等 | 替换为稳定占位符 | 保留联系方式类型，不暴露具体号码或邮箱 |
| 具体地址 | 住宅、办公、送达、项目现场等可定位地址 | 对可定位部分进行替换 | 分析必要的国家、省市、法域或管辖关系可以保留；不得擅自推断 |
| 账户标识 | 银行卡、收款账户、金融账户、登录账户、平台用户标识等 | 替换为稳定占位符 | 保留账户类型、用途、持有人关系及是否为同一账户 |
| 访问凭证 | 密码、私钥、API密钥、访问令牌、会话凭证等 | 从云端副本中移除或替换为不含原值的类型标记 | 不自动还原到报告、协议或其他成品 |
| 本项目案件或资产编号 | 本案案号、产权证号、商标注册号、专利号、车牌等 | 结合上下文判断；能够关联当事人、案件或资产的，默认替换 | 保留编号对应的案件或资产类型，以及跨文件关联 |
| 其他项目定位线索 | 项目专属名称、客户域名、专属系统地址、带身份信息的文件名或链接等 | 能够关联本项目身份的，替换或移除识别性部分 | 保留分析所需的用途、技术结构、地域及关系 |

### 2.1 按上下文判断，不能只按字段名称判断

同一类信息在不同用途下可以采用不同处理方式：

| 场景 | 处理要求 |
|---|---|
| 客户本案的案号，可用于关联具体案件和当事人 | 默认替换 |
| 法律分析引用的公开参考案例案号，与客户身份无关联 | 默认保留，支持核验引用 |
| 客户持有的商标、专利或房产编号 | 默认作为项目资产标识处理 |
| 与客户身份无关联的公开知识产权研究资料编号 | 通常保留 |
| 银行作为本项目贷款人、收款行或担保权人 | 根据项目身份保护需要替换名称，保留银行角色及相关事实 |
| 一般性介绍银行制度，或引用监管规定中的机构名称 | 默认保留 |
| 法院、监管机关作为法律引用或管辖分析背景 | 不因属于机构名称而一律替换；如构成项目定位线索，再结合上下文处理 |

“信息公开”不等于“与本项目身份关联后仍可无条件保留”；反之，也不能因为信息属于案号、机构名或注册号就一律删除。

## 3. 默认原样保留的实质内容

以下内容默认保留，以保障计算、时间线、法律判断及报告质量：

- 金额、估值、收入、成本、税额、赔偿额、债务金额。
- 股权比例、利率、费率、分配比例及计算公式。
- 日期、期限、时间先后及履行节点。
- 合同条款、权利义务、付款条件、交付条件、违约安排、争议解决机制。
- 行业、法域、业务类型、数据规模及其他分析必要的业务属性。
- 当事人角色、股权链、交易链、资金流向、担保关系及事实关联。
- 材料记载、证据限定、未核实事项、争议、分析、推理和结论。
- 法规名称、条号及与客户身份无关联的公开参考资料。

禁止以下默认操作：

1. 对金额等比缩放，或用虚构金额替换真实金额。
2. 平移、随机化日期，导致期限、时效或履行判断失真。
3. 为了隐藏主体而删除其业务角色、权利义务或关系。
4. 将“未提供证明”改成“事实不存在”，或将“拟议事项”改成“已经完成”。
5. 用本地模型摘要替代完整必要语境，却不说明信息删减。

如果实质内容本身构成明显的项目定位线索，应按第5节处理，不得默默改动分析依据。

## 4. 健康、家庭、收入等个人相关事实

此类内容不按字段名一律删除，也不因姓名已替换就一律允许发送。应结合任务必要性和识别风险判断。

处理要求：

- 与任务直接相关的必要事实，在身份处理后保留。例如劳动争议中的工资、入职时间、病假及医疗期相关事实。
- 与任务无关的详细信息，从出站副本中剔除或留在本地。例如合同审阅不需要的家庭成员详情或完整病史。
- 能以较少信息完成分析的，优先发送必要部分，并明确资料边界。
- 对罕见病情、具体行踪、特殊身份、未成年人等高风险内容，增加出站判断，不以占位符替换作为自动放行依据。
- 不将健康、婚姻、收入、前科等所有属性不分情形地统一标注为法定敏感个人信息；法律分类与技术处理策略应分别记录。

## 5. 组合识别风险与内容保密

### 5.1 组合识别风险

即使姓名和公司名已替换，以下组合仍可能暴露具体项目：

- 特定地区唯一一家某类企业，加准确交易日期及罕见交易金额。
- 特殊职位、罕见事件、精确时间与地点的组合。
- 可公开检索的独特项目描述或多项资产线索。

系统发现明显组合风险时，应标记相关段落及判断理由，选择以下处理方式之一：

1. 在不损害分析的前提下，减少不必要的定位性细节。
2. 将高风险部分留在本地，仅发送必要的受控材料。
3. 转为本地分析，或提交人工决定适用的处理路径。

不得为通过校验而擅自改动金额、日期、股比或关键事实。自动检测无法保证穷尽所有重识别方式，产品不应作绝对匿名承诺。

### 5.2 内容保密

隐藏主体身份，不等于消除商业秘密、委托保密义务或其他内容层面的限制。

即使金额、条款和技术内容默认保留，是否可以发送给某个云端服务，仍应由独立的出站政策判断，结合任务授权、服务条款、访问控制及适用义务决定。脱敏通过不得自动覆盖既有禁止出云的限制。

## 6. 占位符、映射与本地还原

### 6.1 占位符一致性

- 同一事项内，同一主体在不同文件、简称、全称及不同提法中应使用一致的占位符。
- 不同主体不得因名称相似而被错误合并。
- 不同事项的映射应相互隔离，不默认复用身份对应关系。
- 占位符应保留主体类型，必要时通过另列角色字段保留业务角色。
- 同一账号、同一资产或同一案件在不同材料中应保持可追踪关联。

示例：

原文：

> 华岚科技有限公司于2027年3月1日向远川银行借款200万元，由陈明提供保证，收款账号为某具体账号。

云端副本：

> [公司A]于2027年3月1日向[银行B]借款200万元，由[自然人C]提供保证，收款账号为[账户D]。

主体身份被替换，金额、日期、借款方向及保证关系保持不变。以上名称仅为示例。

### 6.2 映射隔离

- 原始文件、真实值与占位符映射、复原密钥均留在受控本地环境。
- 云端模型及其工具不得访问原件目录、映射表、其他事项或复原接口。
- 普通日志、报错和运行状态不得包含原始标识符或凭证值。
- 任务应绑定材料版本、映射版本及脱敏规则版本，禁止在历史任务中静默切换。

### 6.3 还原控制

- 仅在本地依据本次任务绑定的映射进行还原。
- 未知、被改写或无法匹配的占位符应报错或转人工处理，不能猜测真实值。
- 凭证类内容不进入普通成品自动还原流程；原件的本地留存按另行确定的文件管理规则处理，本要求不授权删除原件。
- 模型原稿、本地还原稿、人工修订稿应分别保存，能够追溯版本及修改来源。

## 7. 文件层面的覆盖要求

检查范围应覆盖**所有实际会发送给云端的内容**，不能只检查正文段落：

- 正文、表格、页眉页脚、脚注、尾注。
- 批注、修订记录、隐藏工作表或隐藏文本等可能进入出站包的内容。
- 文件名、路径、文档属性、作者信息、链接及附件名称。
- 扫描件或图片中的文字，以及图章、签名、人脸、二维码等识别性内容。

如果只向云端发送经过校验的提取文本，应确保原始文件、页面图像及其元数据未被随包发送。

不能可靠解析或识别的内容应明确标记处理不完整，并阻止自动发送；不得因未提取到文字就视为不存在敏感信息。

## 8. 实现原则

1. **确定性规则、本地语义识别与独立出站扫描共同工作。**不能完全依赖模型识别结果。
2. **三种业务模式共享基础保护。**个人案件、企业事务、尽调可以改变业务提示和识别重点，但案号、机构、账户等不能因模式选择而失去必要保护。
3. **识别能力与替换决策分开。**先识别候选及上下文，再判断是否涉及本项目身份、是否属于公共引用及应如何处理。
4. **数字规则必须控制误报。**不得用裸“7位以上数字”识别所有商标号或账号，应结合字段标签、上下文及格式判断。
5. **处理重叠及长内容。**身份证与银行卡候选重叠、账号与金额混淆、凭证内部数字误识别、跨行及跨分块私钥均应有明确策略。
6. **校验失败时停止出站。**识别不完整、仍有确定性标识残留、凭证残留或映射异常时，不得由模型自行批准放行。
7. **输出审阅依据。**本地可查看识别位置、类型、处理方式及保留理由；云端仅获得完成校验的工作包。
8. **规则变更可追溯。**升级后执行针对性回归，明确旧任务继续使用旧版本还是需重新处理，避免覆盖既有证据链。

## 9. 最低验收标准

以下均使用虚构或合成资料测试。测试结果应区分规则层、本地模型层、完整处理链和实际云端边界，不能相互替代。

| 验收场景 | 预期结果 |
|---|---|
| 身份证、手机号、邮箱及明确标注的长短账户号 | 相关真实值不进入云端副本 |
| 本案案号、客户产权号及客户商标／专利号 | 按项目身份上下文替换，跨文件保持一致 |
| 公开参考案例案号、法规条号 | 保留，不破坏引用核验 |
| 银行作为本项目交易方与一般制度介绍中的银行名称 | 根据角色分别处理，不采取一刀切规则 |
| 金额、估值、股比、利率、日期、期限及公式 | 与原始材料一致，计算结果及时间关系不变 |
| 本地模型漏报明确标识符 | 独立出站扫描对已覆盖模式予以拦截；覆盖范围及不足明确记录 |
| 密码、密钥、令牌及跨行私钥 | 云端不可见，普通成品不自动复原 |
| 相同主体多文件出现、名称相似的不同主体 | 前者一致，后者不误合并 |
| 委托事项相关与无关的个人健康、家庭信息 | 保留必要事实，无关细节不默认发送 |
| 明显组合识别风险 | 触发提示或受控处理，不能通过篡改金额日期自动消除告警 |
| 批注、文件名、元数据、图片或扫描件 | 实际出站内容均被覆盖，无法检查时标记不完整并停止自动发送 |
| 云端输出未知或变形占位符 | 本地拒绝猜测还原，转人工处理 |
| 不同事项同时运行 | 原件、映射及结果相互隔离，不串用身份 |
| 修改规则、模型或映射版本 | 记录变化，历史结果不被静默覆盖 |

技术团队应交付：规则及上下文决策说明、已覆盖与未覆盖格式清单、合成测试用例、漏报与误报记录、本地映射与还原说明，以及出站边界验证结果。

不得仅以“已启用某实体类型”或“若干样本通过”宣称全部文件均能安全发送。

## 10. 法律定位与参考依据

本方案是一套产品与工程处理要求，不代替具体事项的法律判断或发送授权。

去标识化与匿名化应明确区分：本地仍保留映射并可复原的工作流，不应仅凭名称替换就宣称信息已匿名化，或不再属于个人信息。

参考来源：国家互联网信息办公室，《促进和规范数据跨境流动规定》答记者问，2024年3月22日，第5问。该问说明了个人信息、去标识化及匿名化的区别。
