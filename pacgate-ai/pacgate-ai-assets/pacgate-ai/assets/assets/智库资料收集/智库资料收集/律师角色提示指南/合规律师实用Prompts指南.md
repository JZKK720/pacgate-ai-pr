> **使用说明**：以下 prompts 为可直接复制使用的指令模板，`【】`内为需替换的变量。结合 AI系统的联网搜索、华宇元典法律数据库、docx/PDF文档生成、多语言翻译等能力使用。
> **数字时效提示**：模板中出现的申报门槛、期限、比例、条文号等具体数字均以撰写时点为准、仅作示意，实际使用时一律以检索到的现行有效规定为准。
> **通用约定**（适用于本指南全部 prompts）：

> ③ 所有法规与案例引用须标注名称、文号/条文号、效力状态与检索来源，检索不到的明确说明，严禁编造；

## 一、数据合规（Data Compliance）

### 1.1 数据跨境传输评估

```
请生成一份个人信息出境合规评估清单，用于判断应采用哪种出境路径：

企业情况：
- 运营主体：【XX公司，中国境内注册】
- 数据接收方：【境外关联公司 / 第三方SaaS服务商 / 云服务商】，位于【美国/欧盟/新加坡】
- 出境数据类型：【员工数据、客户数据、用户行为数据】
- 数据量级：【约XX万人，XX万条】

评估框架：
1. 出境路径选择决策树：
   - 路径A：通过国家网信办数据出境安全评估
     （适用条件：关键信息基础设施运营者 / 处理100万人以上个人信息 / 累计出境10万人以上等）
   - 路径B：订立个人信息出境标准合同（SCC）
     （适用条件：非CIIO、未达安全评估阈值）
   - 路径C：个人信息保护认证
     （适用条件与流程）

2. 出境前评估内容（无论哪条路径都需要）：
   - 出境目的、范围、方式的合法性、正当性、必要性
   - 境外接收方所在国家/地区的数据保护水平评估
   - 境外接收方的数据安全保护能力评估
   - 个人信息主体权益保障机制（行使权利的渠道）
   - 境外接收方承诺承担的义务
   - 出境后个人信息再转移的处理

3. 所需文件清单：
   - 数据出境场景说明
   - 数据分类分级清单
   - 境外接收方尽职调查报告
   - 标准合同/安全评估申报材料
   - 个人信息保护影响评估（PIA）报告

请输出决策流程图和文件清单表格。
引用《数据出境安全评估办法》《个人信息出境标准合同办法》《促进和规范数据跨境流动规定》等最新规定。
使用华宇元典数据库检索最新法规和指南。
```

### 1.3 GDPR 与 PIPL 对比分析

```
请对比分析GDPR与中国《个人信息保护法》（PIPL）的异同，为跨国企业提供合规建议：

对比维度：

| 维度 | GDPR（欧盟） | PIPL（中国） | 差异分析 | 合规建议 |
|------|-------------|-------------|---------|---------|

1. 适用范围（地域管辖）：
   - 设立地标准 / 目标指向标准 / 国际数据处理
   - "个人信息"定义差异（GDPR的identifiable vs. PIPL的识别范围）

2. 合法处理基础：
   - GDPR六项合法基础 vs. PIPL六项合法性基础
   - "同意"标准的差异（明示同意 vs. 明确同意）
   - "合同必要"的理解差异
   - PIPL独有的"单独同意"要求

3. 数据主体权利：
   - 知情权、访问权、更正权、删除权
   - 数据可携权的差异（GDPR有 / PIPL无明确）
   - 自动化决策相关权利
   - 死者个人信息保护

4. 数据处理者义务：
   - DPIA vs. PIA的适用场景差异
   - 数据保护官（DPO）vs. 个人信息保护负责人的要求差异
   - 记录处理活动的要求

5. 数据泄露通知：
   - 通知时限（GDPR 72小时 vs. PIPL"立即"）
   - 通知对象（监管机构 + 数据主体）
   - 通知内容要求

6. 数据跨境传输：
   - 充分性认定 vs. 安全评估/SCC/认证
   - 标准合同条款的内容差异
   - 本地化要求的差异

7. 监管执法：
   - 罚款上限（GDPR 4%全球营业额 vs. PIPL 5000万/5%）
   - 执法风格差异
   - 集体诉讼/公益诉讼机制

8. 特殊数据处理：
   - 敏感数据处理差异
   - 儿童数据处理差异

请输出完整对比表格，并针对"在中国和欧盟均有业务的跨国企业"给出统一合规框架建议。
```

### 1.4 隐私政策审阅

```
请审阅以下App/网站的隐私政策，依据中国法律法规进行合规审查：

【上传隐私政策文本或粘贴内容】

审查依据：
- 《个人信息保护法》
- 《网络安全法》
- 《数据安全法》
- 《App违法违规收集使用个人信息行为认定方法》
- 《常见类型移动互联网应用程序必要个人信息范围规定》
- GB/T 35273《信息安全技术 个人信息安全规范》
- 《个人信息处理中告知和同意的实施指南》

逐项审查清单：
1. 告知完整性：
   - 是否完整披露处理者身份与联系方式
   - 是否列明所有个人信息收集类型（含SDK收集的）
   - 是否说明处理目的、方式、范围
   - 是否说明存储期限与删除策略
   - 是否告知第三方共享/委托/转让的情况

2. 同意有效性：
   - 是否区分"基本功能必要信息"和"非必要信息"
   - 是否提供逐项同意机制
   - 是否有"不同意即退出"的捆绑同意问题
   - 敏感信息是否取得"单独同意"

3. 用户权利保障：
   - 是否告知查阅、复制、更正、删除、撤回同意的途径
   - 是否告知注销账号的方法
   - 是否告知投诉渠道

4. 第三方共享：
   - 是否列明所有第三方SDK及其收集信息
   - 是否说明共享目的与数据类型
   - 是否提供第三方清单的可查阅链接

5. 跨境传输：
   - 是否告知数据出境情况
   - 是否说明出境合规路径

6. 未成年人保护：
   - 是否有专门的未成年人信息保护规则
   - 14岁以下是否需要监护人同意

输出格式：
- 逐条标注不合规之处（🔴违法 / 🟡风险 / 🟢建议改进）
- 给出修改建议文本（直接可用的修改前后对比）
- 生成合规评分表（各维度得分）
```

### 1.5 数据安全事件应急预案

```
请起草一份数据安全事件应急处置预案，适用于【互联网企业/金融机构/医疗机构】：

预案结构：

1. 总则
   - 适用范围
   - 工作原则（及时性、最小损害、合法合规）

2. 事件分级标准
   - 特别重大（红色）：泄露【100万条以上个人信息 / 重要数据 / 核心数据】
   - 重大（橙色）：泄露【10万-100万条个人信息 / 敏感个人信息1万条以上】
   - 较大（黄色）：泄露【1万-10万条个人信息】
   - 一般（蓝色）：泄露【1万条以下个人信息】
   - 每级对应的响应级别和审批层级

3. 应急响应组织架构
   - 应急领导小组（CEO/CTO/CPO/DPO）
   - 应急执行小组（安全/法务/公关/客服/IT）
   - 各角色职责矩阵

4. 处置流程
   阶段一：发现与报告（0-1小时）
   - 发现渠道（内部监测/外部报告/用户投诉）
   - 初步评估与上报流程
   - 启动应急响应的决策机制

   阶段二：评估与遏制（1-4小时）
   - 事件影响范围评估
   - 证据保全措施
   - 遏制措施（断网/封禁/删除/回滚）

   阶段三：处置与恢复（4-24小时）
   - 系统修复与漏洞修补
   - 数据恢复方案
   - 影响用户范围确认

   阶段四：通知（依法及时）
   - 监管报告义务：
     * 网信部门报告（触发条件、报告内容、时限）
     * 行业主管部门报告
     * 公安机关报告（如涉犯罪）
   - 数据主体通知义务：
     * 通知触发条件
     * 通知内容（事件描述、影响范围、应对措施、用户自我保护建议）
     * 通知方式（短信/邮件/公告/电话）

   阶段五：总结与改进（事后7-30天）
   - 事件调查报告
   - 根因分析
   - 整改措施与跟进
   - 内部问责

5. 对外沟通口径
   - 媒体回应原则与模板
   - 用户沟通模板（短信/邮件/公告）
   - 监管沟通策略

6. 附件
   - 应急联系人名单（模板）
   - 监管部门联系方式清单
   - 数据安全事件报告模板
   - 用户通知模板

引用《数据安全法》第29条、《个人信息保护法》第57条等。
输出为Word文档。
```

## 二、AI 与大模型合规（AI & LLM Compliance）

> **为什么全新新增？** 2023-2026年，AI与大模型合规从数据合规的"子模块"成长为独立的合规业务线——中国有深度合成/生成式AI备案制度，欧盟有AI Act分级监管，美国有NIST AI RMF+州级立法，东南亚各国也在密集出台AI治理框架。律师需要一套独立的prompt体系来处理AI产品的全生命周期合规。

### 2.1 中国AI产品合规——备案与许可路径分析

```
请分析以下AI产品在中国境内的合规路径，重点关注备案/许可义务：

### 6.1 反垄断合规风险评估

```

## 十二、跨境合规方法论（Cross-border Compliance Framework）

> **为什么全新新增？** 律师处理跨境合规时，最大的挑战不是"某个领域的法规"，而是"不同法域之间的冲突与协调"——中国PIPL vs. 欧盟GDPR vs. 美国州级隐私法 vs. 东南亚各国数据法的交叉适用；中国AI备案 vs. 欧盟AI Act vs. 美国NIST RMF的合规标准差异；制裁合规与反制裁法的冲突。本模块提供一套跨境合规的通用方法论框架，适用于任何合规领域。
