Step 5 本地复杂推理 —— 评测方案模板
目的：用数据回答一个决定成本结构的问题——本地 Main（Nemotron3:33b）跑中国
法 NDA/合同复杂风险分级，是否够好到让 Step 5 大部分时候不升级云端？ 产出：
一个可重复执行的评测，输出"本地够用率"和"升级阈值"，供路由器轴 A 调参。 配套：
《百宸NDA审查Skill_三层混合云架构改造.md》。

一、为什么需要它
"效果够好"目前是感觉，不是决策依据。三层架构的省钱逻辑全压在 Step 5：

若本地 Main 接近云端 → Step 5 默认本地、云端兜底 → 省 token 成立。
-
若差距大 → 高风险事项必须保留云端升级 → 成本回升，需重新算账。
-

这个评测把"够不够好"变成一个有阈值、可判定的结论。

三、金标准数据集
规模：起步 50 份，目标 100–150 份 NDA/商业合同（覆盖单/双向、中外主体、不同行业、含"陷阱"
样本）。
标注：每份由 ≥2 名百宸律师独立标注，分歧由第三人裁定，形成 gold label：
1. 整体分级：GREEN / YELLOW / RED。
2. 问题清单：每个应识别的问题（如"缺独立开发例外""永久保密""内嵌挖角条款"），含条款定
位。
3. 修改话术（可选）：律师认可的改法，用于评 Step 5 输出的可用性。
脱敏：全部先过 Step 2 去标识化关卡，确保 CLOUD 被测项收到的是脱敏包（同时也顺带验证了
去标识化质量）。
版本化：数据集打 tag 存档，法规更新后可重跑回归。
四、评测指标
1. 风险分级一致性（最关键）
- 准确率：模型分级 = gold 分级 的比例。
- 危险错误率（重点盯）：把 gold=RED 判成 GREEN/YELLOW 的比例 = 漏报高风险。法律
场景下这是最致命指标，单独设红线（如 ≤ 2%）。
- 用混淆矩阵呈现，不只看总准确率。
2. 问题识别召回率 / 精确率
- 召回：gold 问题被识别的比例（漏报 = 风险）。
- 精确：识别出的问题中真问题的比例（虚报 = 浪费律师时间）。
- 法律上召回优先于精确——宁可多报让律师删，不可漏报。
3. 修改建议可用性（人评，抽样）
- 律师对 Step 5 给的修改话术打分：直接可用 / 小改可用 / 不可用。
4. 置信度校准（决定升级阈值能不能用）
- 让本地 Main 对每次分级输出一个置信度，画可靠性曲线：低置信时是否真的更易错？
- 校准好 → 可用"低置信→升级"省钱；校准差 → 升级触发器失效，需改用规则触发。

5. 成本/延迟（旁证）
- 每条样本的本地耗时 vs 云端 token 成本，估算不同阈值下的月度成本。
五、判定规则与阈值
本地够用的判定（示例，百宸据风险偏好定）：
- 危险错误率（RED→低估）：LOCAL-MAIN ≤ 2% 且不显著高于 CLOUD-CN；
- 整体分级准确率：LOCAL-MAIN ≥ CLOUD-CN − 5pp；
- 问题召回率：LOCAL-MAIN ≥ 85%。
- 满足 → Step 5 默认本地；不满足 → 见下。
升级阈值的产出（路由器轴 A 用）：
- 若置信度校准良好：定一个置信阈值 τ，本地分级置信 < τ → 升级境内云。在评测集上调 τ
，使"升级后危险错误率达标"且"升级比例最小"。
- 若校准差：改规则触发——高风险信号（金额、RED 倾向、新型条款、法源冲突）强制升级
，与置信度无关。
- 硬规则（不可调）：gold 维度里属高风险类目的事项，一律强制升级（云或人），不靠模型自
评。
六、执行流程
1. 建集：50→100+ 样本，双标注 + 裁定，过 Step 2 脱敏。
2. 跑测：同一脱敏输入喂 5 个被测项，固定 prompt/温度，各出分级+问题+置信度。
3. 计分：脚本算混淆矩阵、召回/精确、校准曲线、成本。
4. 抽样人评：律师评修改话术可用性。
5. 判定：对照第五节阈值，出结论 = {Step5 默认本地 / 默认境内云 / 混合阈值 τ}。
6. 归档 + 回归：数据集与结果版本化；模型或法规更新后重跑。
七、复用
同一套方法换 gold 维度即可评其他 skill 的复杂推理步：合同审查、隐私 DPA 审查、劳动解雇审
查。每条 skill 线都应有自己的金标准集与本地够用判定，不可用 NDA 的结论替代。

八、待百宸决策
1. 危险错误率红线定多少（2%？1%？）——直接决定多少事项被迫升级。
2. 金标准标注由哪几位律师负责、裁定人是谁。
3. 起步样本量与覆盖面（行业/单双向/涉外比例）。
4. 是否纳入 CLOUD-INTL 作天花板参照（涉脱敏数据出境，需合规确认）。
