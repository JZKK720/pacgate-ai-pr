# Frontend overlay build contract

`deploy/frontend-patches/files/` is copied wholesale over a clean checkout of
`deploy/deer-flow-src/frontend` after CI clones upstream at the pinned tag, and
inside `deploy/deer-flow-frontend-pacgate/Dockerfile` the image copies the same
tree. That means **every file here must survive a fresh checkout unchanged**.
Anything derived (like the pnpm lockfile, or an installed node_modules) must
either be committed as part of the overlay or regenerated by a declared build
step.

## Files that must travel with the overlay

| Overlay file | Why it is required |
|---|---|
| `pnpm-workspace.yaml` | Adds one `overrides` entry: `next` / `eslint-config-next` -> `16.4.6`. Upstream pins 16.4.1, which the registry flags and `next build` refuses to run (SecurityFatalError). The Dockerfile and CI both install before building, so without this file the build cannot start. |
| `pnpm-lock.yaml` | Resolved against that override. Without it `pnpm install --frozen-lockfile` fails because the lockfile names 16.4.1. |
| everything under `src/` | Branding, zh-CN strings, model selector fix, sanitizer UI, and the gateway `/api/*` proxy behaviour. |

`package.json` itself is **not** overridden: the override lives in
`pnpm-workspace.yaml`, matching how upstream already carries its own two
overrides there.

## If this breaks, the symptom is

`pnpm build` exits non-zero on a clean checkout with
`SecurityFatalError: Your version of Next.js is affected by a known security vulnerability.`
That means the overlay's `pnpm-workspace.yaml` (or `pnpm-lock.yaml`) did not
arrive; check the copy step in `deploy/build-frontend.ps1` and the clone+copy
steps in `.github/workflows/build-ghcr.yml` before touching the Dockerfile.
