# INCIDENT 2026-10-04: third occurrence — I printed the qm sandbox's whole secret set

## What happened

While checking whether the qm core was wired to the (unobtainable) sandbox image,
I ran:

    docker exec qm-pacgate-core sh -c 'env | grep -i -E "fly|sandbox" | sort'

The grep pattern `fly|sandbox` matched **`FLY_RESIDENT_ENV_*`** — by design the
complete set of secrets handed to resident sandboxes. Seven values printed:

- `FLY_RESIDENT_ENV_FIRECRAWL_API_KEY`
- `FLY_RESIDENT_ENV_OPENVIKING_ROOT_API_KEY`
- `FLY_RESIDENT_ENV_OPENVIKING_API_KEY`
- `FLY_RESIDENT_ENV_PACGATE_API_PASSWORD`
- plus the non-secret `OPENVIKING_ACCOUNT` / `OPENVIKING_USER` / URLs

I wanted `FLY_BASE_IMAGE` and `SANDBOX_BACKEND` — which are not secrets. A grep
for "sandbox-ish" keys dragged the secret set in with them.

## The rule I broke

This is the **third** time in this repo (see the 2026-09-18 PAT and the
2026-09-23 `ov.conf` incidents, above). Both prior lessons apply and neither was
enough:

- 2026-09-18: *never print a raw response body in an auth flow.*
- 2026-09-23: *never read a credential-bearing file and then decide how to
  filter it.*

The generic form neither captured: **`env | grep <loose pattern>` on a container
is a credential-bearing read.** Any dump of a container's environment can contain
secrets, and a *broad* pattern guarantees you get the ones you did not ask for.
The safe shape is to name the exact variables:

    docker exec <c> printenv FLY_BASE_IMAGE SANDBOX_BACKEND

Not `env | grep`, and not a pattern that can match a prefix family.

## What should be rotated

Scoped by where each value can actually be used:

1. **`FIRECRAWL_API_KEY` — rotate this one.** It is a third-party service
   credential (`fc-` prefixed, 32 hex chars). Anyone with the transcript can use
   it against Firecrawl's API from anywhere. This is the only exposed value with
   reach beyond this machine.
2. **OpenViking root + app keys — low.** Locally generated by `install.ps1`
   (`.env.example` ships `change-me`, and `install.ps1` replaces it), and the
   service binds localhost. Rotating is cheap if wanted.
3. **The qm bridge password — low.** I generated it earlier in this session
   (32-byte CSPRNG hex), and it authenticates only against the local
   `pacgate-api`. It is also now the value in qm's `.env`.

## Note on provenance found while checking

`setup-qm.ps1:271` reads `FIRECRAWL_API_KEY` out of the **main bundle's** `.env`
and `:345` writes it into qm's. Worth knowing for rotation: it must be changed in
the main `.env` and then re-staged, or qm keeps the old one.
