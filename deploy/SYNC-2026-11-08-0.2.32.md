### Why the memory query-param fix was dropped

`test-release-provenance.ps1` reported both `deploy/frontend-patches/files/src/app/api/memory/*.ts` files as COPY-reachable changes after the build revision, so a rebuild from `v0.2.32` would differ from what clients pull.

Measured before dropping it: no shipped caller passes a query string. `src/core/memory/api.ts` calls the base route and the `facts`/`export`/`import` paths with none, and the running `0.2.6` frontend image does not contain the fix either. It was defensive, not load-bearing, so upstream's version was restored and provenance went green.

### Pull reliability note

The 8 GB model layer took five attempts over ~2.5 hours. Every attempt returned HTTP 200 from `/api/pull` but the blob transfer died with `context deadline exceeded` against `registry.ollama.ai` and the R2 CDN. Ollama's chunk state persists across attempts, so progress accumulated (57.7% -> 75.8% -> 86.4% -> 97.3% -> complete). A retry loop, not a single long call, is what completes this pull on this network.
